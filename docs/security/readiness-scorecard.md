## Bottom line

**The product is built, verified, secure, and deployed.** That last word is what
this file was missing: P0–P7 shipped, and three further passes shipped on top.
Backups run nightly, in-region, with a restore drill that actually passed.

The two hardening items that had been sitting as "prepared, verify at bring-up"
— the least-privilege DB role and the database-enforced append-only audit log —
were **reported** done at bring-up, and the part of that report the runbook
actually re-checks is that the app role cannot DELETE from `AuditLog` and is not
a superuser. The rest of the claim (no CREATE on schema `public`, UPDATE
revoked, full DML on `Submission` for contrast) has no command behind it in this
repo. That is not a suspicion that it is false; it is the difference between
"verified" and "verified in the way this project promises", and this file exists
to keep those apart.

What remains splits cleanly into three kinds of work, and only the first is
short. **Founder-only, blocking an announcement:** the SMTP credential, a
secondary on-call contact, and counsel review of the legal pages. **Engineering,
unblocked and small:** getting `main`'s CI green again (a Prettier run and one
evidence-rail assertion), a monitor pointed at `/api/v1/ready`, an error-tracker
DSN, CAA records, and a recorded `sec-web` grade. **A project in its own right:**
the ADR-0004 edge migration off Cloudflare, which is gated on a co-tenant's
agreement, must be sequenced in the order the ADR sets, and is the only thing
standing between the site's current qualified residency wording and an
unqualified one.

The temptation this file exists to resist is rewriting that last claim early.
The public wording changes in the same deploy as the DNS cutover — never ahead
of it.
