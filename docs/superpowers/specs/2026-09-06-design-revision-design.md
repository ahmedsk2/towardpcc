# Design revision — buttons, motion, catalogue, calculator text diet

- **Date:** 2026-09-06
- **Status:** executed 2026-09-06/07 in #179, #180, #181, #182 and the docs PR
  that carries this file; plan in
  `docs/superpowers/plans/2026-09-06-design-revision-plan.md`.
- **Proposal board:** https://claude.ai/code/artifact/2be530b7-3f80-444a-8883-734f29dde984
- **Amends:** `docs/design/motion.md` (one addendum, below);
  `docs/decisions/ADR-design-direction.md` (one addendum, below). Palette,
  type, focus idiom and the privacy invariants are untouched.

## 1. The brief

The founder's words: revise the design, keep the palette, focus on buttons,
hover effects and motion; make the calculators look like the reference
(pemcalc.com, a card toolkit with labels-and-inputs calculators); cut the
amount of text inside each calculator, or move it behind a hover/tap
disclosure where it cannot be cut; make the site look top-notch, attractive
and easy to use; remove the marks that make it read as generated by an agent,
such as the "live" status pill in the hero.

Answers to the four design questions:

| Question                      | Answer                                                     |
| ----------------------------- | ---------------------------------------------------------- |
| Button shape                  | Pill everywhere, with a colour gradient and a hover effect |
| Field guidance                | All behind the ⓘ; condense any help text that is too long  |
| Catalogue card description    | Founder reviews 25 drafted one-liners before merge         |
| Which generated-looking marks | Design lead's judgement (all four groups listed in §4 go)  |

## 2. What was measured first

- A median calculator ships **≈310 words** of prose before the references;
  the largest (PIM3) ships 1,569. Per-field help averages **31 words** across
  135 fields; the longest single help text is 223 words (PIM3), then 176
  (KDIGO), 106 (Phoenix), 101 (pSOFA), 96 (PRISM). Measured by
  `text_volume.py` over `packages/scoring-engine/src/scores/*.ts`.
- Route JS: `/calculators` 158.7 KB, `/calculators/[slug]` 155.9 KB gzipped
  against the 170 KB gate. **No library may be added.** Every motion item is
  CSS.
- pemcalc's calculator page carries no field guidance at all: a label, an
  input, a Calculate button. Ours keeps every clinical sentence but moves it
  one gesture away.
- The site currently runs three button idioms (marketing pills, square
  outlined form buttons, underlined text resets), each with its own hover,
  press and focus recipe.

## 3. One button family

`packages/ui/src/button.tsx` becomes the single source for every button and
button-shaped link. Shape: **pill** (`rounded-pill`) for all sizes. Inputs and
cards stay soft-rectangle (`rounded-md` / `rounded-lg`), so a control that
takes a value looks different from one that acts.

Variants:

| Variant      | Rest                                                            | Hover / focus-visible                                                                    |
| ------------ | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `primary`    | `--gradient-cta` (accent-deep → accent), white text             | gradient slides to its deeper end, `--shadow-accent` glow, 1 px lift, arrow travels 2 px |
| `secondary`  | white fill, `border-strong` outline, ink text                   | border and text to accent, glow, 1 px lift                                               |
| `quiet`      | no border, `accent-deep` text                                   | `accent-tint` fill                                                                       |
| `icon`       | 44 px circle, `border-strong` outline, muted glyph              | accent glyph and border                                                                  |
| `on-dark`    | white fill, accent text — for the hero and the crimson CTA band | `accent-tint` fill, `accent-deep` text                                                   |
| `ghost-dark` | transparent, `white/50` outline, on-dark text                   | white outline, `white/10` fill                                                           |

Press: `active:translate-y-px`. Focus: the one idiom, `outline-accent`
(`outline-coral` on dark). Reduced motion: colour only, no lift. Transition
names its properties (`color, background-color, background-position,
border-color, box-shadow, translate`), 150 ms, `--motion-ease`.

**The gradient stays inside the contrast-cleared crimsons.** `--gradient-cta`
runs `#8f1728 → #cf1f3d` (white text 9.05:1 and 5.36:1). It must never reach
`accent-bright` (#ea3a57, 4.01:1) or coral, both of which fail AA for 15 px
text. `--gradient-accent` (crimson → coral) remains a surface gradient for
bands and rules, never a button fill. The hover "slide" is a
`background-position` shift over a `background-size: 160% 100%` gradient, so
the hover state is still drawn from the same two stops.

Sizes: `md` 44 px / 20 px padding (the floor for every tappable control),
`lg` 48 px / 24 px for hero CTAs, `sm` 36 px for chips-that-act.

Every hand-rolled button and button-shaped `<Link>` in `apps/web` moves onto
`buttonClasses()`. A source scan (`content/button-idiom.test.ts`) fails the
suite if a `className` under `app/` or `components/` contains both
`min-h-1[12]` and `rounded-(md|full)` without coming from `buttonClasses` —
the same shape of guard as `countup-scope.test.ts`, asserting a property the
family exists to hold.

## 4. The marks that go

All four groups, on the design lead's judgement:

1. **Home hero (parked at `/home`, restored later unchanged):** the pill badge
   "Live now · 25 referenced calculators" with the pinging dot; the stat trio
   ("25 Calculators live / 87 Cited references / 0 Bytes transmitted — proven
   by test →"); the four icon-chip feature cards overlapping the hero. Replaced
   by one quiet line under the CTAs, derived at render:
   `{liveCalculators} calculators · every one referenced · nothing you enter leaves your browser`.
   The counter band lower on the page keeps the figures and the count-up.
   `figures.test.ts` re-pins the count to the new line's placeholder;
   `published-figures.spec.ts` keeps asserting the counter band.
2. **Catalogue:** the "25 LIVE · EVERY ONE REFERENCED" eyebrow, the "25 live"
   chip at the bottom, the ✓ prefix on the active filter chip, the `/` kbd
   hint, the hidden "Open →" ghosts, "v1.0.0" on every card.
3. **Pillar cards on home and pillar-page hero badges:** the pills with dots.
   Where a status qualifies a public claim ("piloting", "pilot underway") it
   survives as plain muted text in the card meta line; "Live now" and
   "Free · capacity-based" disappear (a live product needs no badge; "free" is
   already in the body copy).
4. **Calculator page furniture:** the four-cell CATEGORY / VERSION /
   REVIEWED / VALIDATION instrument row becomes one mono meta line
   (`Organ dysfunction · v1.0.0 · Reviewed 3 Sep 2026 · Validation pending`);
   breadcrumbs go to sentence case; "Source: … — full citation in Evidence,
   below." becomes `Source: Leteurtre 2013`; the privacy Callout becomes one
   sentence with a link (§6).

Not removed: the `Eyebrow` rule-and-label device on home sections (a
signature, used with restraint), the counter band, the honest validation
badge in the Version tab (PRD §6.4 requires it), the disclaimer (PRD §6.6),
and every figure — figures move, none is dropped.

## 5. The catalogue as a toolkit

`/calculators`:

- **Hero** keeps the gradient band and title; the eyebrow goes. The search
  box moves INTO the hero as a large white pill (`PageHero` gains a `children`
  slot). Placeholder: "Search by name, condition or drug". The `/` shortcut
  keeps working; the hint glyph goes.
- **Filter chips** below the hero: pill, `sm` size; the active chip is solid
  crimson with white text and `font-semibold` (luminance inversion plus weight
  is the non-colour cue); counts stay inside the chip.
- **Cards** in a grid: 1 column under `sm`, 2 to `lg`, 3 from `lg`. Each card
  (`<li>` with the stretched-link pattern — a `<button>` may not nest inside
  an `<a>`): category glyph in an `accent-tint` square, the **short name**
  (`shortName()` from `content/score-description.ts`), the **tagline** (§7),
  input count in mono, a visible "Open" with a travelling arrow, and the
  favourite star inside the card's top-right corner. Hover and `focus-within`
  lift 3 px, border to `border-strong`, `--shadow-xl`, and a 3 px
  `--gradient-accent` rule scales in along the top edge (the compound hover
  motion.md revision 4 permits on catalogue cards). Cards arrive with a
  staggered `Reveal` (45 ms, capped at 300 ms).
- Category headings stay as section landmarks but drop the mono uppercase
  treatment for display-face sentence case.
- The favourites note stays; the "25 live" chip goes.

## 6. Inside a calculator: the text diet

Nothing clinical is deleted from the page's accessibility tree. It moves one
gesture away, and the longest entries are condensed at source (§7).

### 6.1 Field guidance behind an ⓘ

Every input whose definition carries `helpText` gets a 22 px circular `ⓘ`
button beside its label (`components/calculator/field-help.tsx`):

- **Hover or keyboard focus** on the button shows the guidance as a tooltip
  anchored under the label (dark ink ground, page-coloured text, max 44ch,
  clamped to the viewport, `transform`/`opacity` only, 150 ms).
- **Click or tap** pins the same text inline under the field (`aria-expanded`
  true, `data-pinned`); a second click, `Escape`, or pinning another field's
  help unpins it. Touch users therefore have a permanent path: the hover
  variant fires on touch anyway (`@custom-variant hover`), but the pin is the
  designed one.
- The help element is always in the DOM and referenced by the input's
  `aria-describedby`, so screen readers hear the full text exactly as today;
  visually it is `hidden` until pinned. The button carries `aria-controls`
  and an accessible name of `About {label}`.
- Under `prefers-reduced-motion` the tooltip appears without transition.
- Print: the help stays hidden; a printed record needs the chosen values, not
  the field guidance.

### 6.2 The accepted range

Keeps its two homes and loses its third. The placeholder carries the range
while the field is empty (`calculator-layout.spec.ts` asserts this). Once the
field holds a value or a rejection, a mono caption `Accepted 0–30 mmol/L`
appears under it, so the range is on screen whenever a value is being
corrected. The always-visible sentence under every empty field is gone.
`out-of-range.spec.ts` and `reciprocal-unit-hint.spec.ts` are updated to fill
a value before asserting the caption.

Notices (`notice` from the engine: "accepted and then not used") stay inline
and amber, unchanged — they are result-affecting, not reference.

### 6.3 The result rail

- Heading becomes the score's short name (still the `h2` the mobile bar
  focuses), with "Result" as the `aria-label` fallback for scores whose short
  name equals the page title.
- The number, band scale and cut-points are unchanged in behaviour. The band
  sentence changes shape only: `**High.** description` instead of
  `Interpretation: High — description`; the word "Interpretation" survives
  as sr-only text.
- The action row moves to the button family: Copy summary and Copy link as
  `secondary`, Print as `icon`.
- The privacy line becomes one sentence: "Runs entirely in your browser.
  Nothing you enter leaves this device." followed by a link "How" to
  `/trust`. The two facts it used to spell out (copy-link builds a URL on
  demand; reload starts blank) move to the Copy-link button's tooltip and to
  `/trust`, which already states them. This is a public-claim wording change
  and is called out in the PR for the founder.

### 6.4 The reference zone

- Tabs become a segmented pill strip (`Formula · Notes · Evidence ·
Version`); still `role="tablist"`, still four, still printed in full.
- The formula panel is set as a labelled definition list when the prose
  carries clause labels of the form `Label: …` (PELOD-2, PIM3, PRISM, pSOFA,
  Phoenix, KDIGO do); otherwise it stays a paragraph. The splitter
  (`lib/formula-lines.ts`) never changes a word — it only decides line breaks
  — and is unit-tested against PELOD-2 and a label-free score.
- The notes panel keeps its paragraph but gains the 58ch measure and a
  15 px size; the evidence and version panels are unchanged.
- The disclaimer keeps its wording and loses its heading box: one compact
  note at the foot of the page.

### 6.5 What does not move

motion.md's calm boundary holds without exception: the inputs, the computed
number, the band scale and the composition bars get nothing beyond the 150 ms
colour transition. The tooltip is chrome around the field, not the field.

## 7. Content changes in the scoring engine (founder sign-off required)

Two additions to `ScoreDefinition`, both plain data, both reviewed by the
founder in the PR before merge:

1. **`tagline: LocalizedText`** — one line, ≤ 90 characters, stating what the
   score is for, in the register of "Organ dysfunction severity across five
   systems, with predicted in-hospital mortality." Rendered on the catalogue
   card, in the mega-menu item meta, and folded into `matchScores` so a search
   for "mortality" finds PIM3 by what it does. Carried on `ScoreSummary`.
   A registry test asserts presence, length, and no trailing period.
2. **Condensed `helpText`** where the current text exceeds **60 words**. The
   condensation keeps every rule, threshold and prohibition; it removes
   restatement, moves derivation history into `notes` where it is not already
   there, and drops the SHOUTED lead-ins. Each change is listed in the PR
   with before and after. A registry test caps `helpText` at 60 words so the
   ceiling holds for future scores.

Neither touches a formula, a threshold, a reference or a band.

## 8. Motion and interaction, site-wide

- Marketing surfaces (dial 7): the compound card hover from §5 generalises to
  home pillar cards and pillar-page stat cards (already close); nav and footer
  traces are unchanged; the hero rise cascade is unchanged; the four feature
  cards are gone so nothing replaces their reveal.
- Clinical surfaces (dial 3): unchanged. The catalogue is a marketing-adjacent
  surface and may move; the calculator form may not.
- All new motion is `transform`/`opacity`/colour, named properties, tokens
  only, static under reduced motion. 0 KB of JS beyond the pin toggle (a few
  hundred bytes in the existing client component).

## 9. Verification per PR

Fixers first (`pnpm lint --fix`, `pnpm format`), then the full gate, then the
e2e specs that name the touched surface, then a browser pass on the deployed
build at 375 px and 1280 px. Contrast of every new pairing is asserted by
`tokens.test.ts` where it is a token, and computed by hand in the PR where it
is a composition (white on the gradient's two stops). The button-idiom scan,
the tagline test and the help-length cap are the new guards, each made to
fail on purpose once before it is trusted.

## 10. Out of scope

Restoring the home page to `/` (founder's call, unchanged); a dark theme;
persisting form state across reload (Invariant 2); any change to a formula,
threshold, reference or band; the admin surfaces.
